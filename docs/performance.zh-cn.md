# 边界检查性能

Boundra 的性能声明基于可复现的合成工作区，而非对小示例的非正式观察。

## 运行

```bash
cargo build --release -p boundra-cli
pnpm benchmark:boundaries
pnpm benchmark:boundaries:large
```

基准测试会创建具有 1,000 或 10,000 个 TypeScript 源文件的临时应用。每个文件都 import 一个已声明领域的公开 API，因此该测试测量项目加载、import 扫描、别名解析和边界检查，而不产生违规。

报告值：

- 首次运行实际耗时（`cold_ms`）
- 后续运行实际耗时的中位数（`warm_median_ms`）
- 在 `/usr/bin/time` 能提供该信息时，记录观测到的最大常驻内存大小（`max_rss_mb`）
- 操作系统、架构、Node 版本、文件数量和迭代次数

## 回归检查

CI 运行 1,000 文件的冒烟基准测试，并刻意使用较宽松的上限。该检查旨在捕捉灾难性回归，而非正常的 runner 波动。发行决策应比较相同环境下的重复结果。

## 当前基线

2026-07-03 记录的本地基线（`darwin-arm64`、Node 24.14.0）：

| 文件数 | 冷启动 | 热启动中位数 | 峰值 RSS |
| ---: | ---: | ---: | ---: |
| 1,000 | 20.74 ms | 18.92 ms | 2.55 MB |
| 10,000 | 163.32 ms | 164.20 ms | 沙箱中不可用 |

每个候选发行版本应重新运行基准测试，并在对应发行说明中记录存在实质变化的结果。不要将不同硬件的结果视为等价而直接比较。Linux CI 通过 `/usr/bin/time` 报告峰值 RSS。
