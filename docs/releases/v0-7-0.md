# Boundra v0.7.0

## Release Summary

Boundra v0.7.0 makes architecture checks more reliable in CI and development and reduces repeated domain-root lookup work. The release keeps the existing npm package and schema-backed runtime API, with native releases now distributed from Oddmash/boundra.

## Highlights

- Enforce minimum scan coverage with the optional `check-boundaries --min-domains <n>` flag. Insufficient coverage reports `COVERAGE-001` instead of silently passing.
- Index manifest-backed domain roots during boundary analysis and coverage counting; preserve deepest nested-domain matching and deterministic source scan order.
- Normalize HTTP request headers case-insensitively and return bounded error diagnostics without waiting for delayed stream cancellation.
- Show structured CLI/project errors and failed checks in the Vite development overlay instead of clearing diagnostics.
- Add empty-diagnostic summary regression tests.
- Publish complete Korean, Japanese and Simplified Chinese user guides and reference navigation alongside English, and refresh the product introduction and agent-readable documentation.

## Installation

Node.js 20 or later is required. The npm launcher downloads and verifies the native CLI for the matching version.

```bash
pnpm add boundra@0.7.0 zod
pnpm exec boundra --version
pnpm exec boundra check-boundaries --format json --min-domains 2
```

Adjust the domain threshold to your workspace. The native CLI can also be installed from tagged source:

```bash
cargo install --git https://github.com/Oddmash/boundra --tag v0.7.0 boundra-cli
```

Read the [user guide](https://oddmash.github.io/boundra/docs/user-guide/) for a complete two-domain example.

## Breaking Changes

None. The minimum-domain coverage gate is opt-in. HTTP and Vite changes correct erroneous behavior without changing exported signatures.

## Known Limitations

- Static boundary checks do not prove runtime authorization, deployment artifact completeness, or network isolation.
- Conditional and array mappings in root `package.json#imports` are not modeled by the current static resolver.
- The native binary targets Linux x64, macOS Intel/Apple Silicon, and Windows x64. Other targets can use a matching source build when supported.

## Verification

- Rust workspace unit tests, Clippy, nested-domain lookup and deterministic scan ordering regression checks.
- TypeScript workspace checks; runtime, HTTP transport, config, Vite and UI regression tests.
- Node.js 20, 22 and 24 compatibility, clean-room package and framework consumer verification.
- Native Linux, macOS x64/arm64 and Windows CLI validation and benchmark smoke checks.
- Localized browser test, code example parity and link validation.
- The release pipeline requires full validation before publishing the npm package and checksummed native archives.
