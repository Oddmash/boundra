# Boundra v0.8.0

## Release Summary

Boundra expands architecture checks and developer workflows while retaining its existing runtime contract API.

## Highlights

- Inspect domain impact, explain built-in rules, diagnose workspace configuration, and watch saved-file changes.
- Adopt boundaries incrementally using explicit baselines, migration plans, and Git changed-file reports while retaining full scans.
- Export local dependency views, GitHub and SARIF reports, and shell completions.
- Configure additive domain restrictions and integrate boundary results into ESLint.
- Explore read-only architecture MCP and LSP adapters. The VS Code extension remains independently versioned at 0.1.1.

## Installation

```bash
pnpm add boundra@0.8.0 zod
pnpm exec boundra --version
pnpm exec boundra doctor
pnpm exec boundra check-boundaries --format json
```

## Breaking Changes

None intended. Baselines and domain restrictions are opt-in; the built-in rules retain their behavior.

## Known Limitations

- The incremental scan experiment is not enabled by default.
- The ESLint adapter uses a single scan snapshot; run the full checker in CI.
- MCP and LSP are previews, not production editor or security integrations.
- Static checks do not prove runtime authorization or deployment isolation.

## Verification

The integration runs the Rust workspace tests and Clippy alongside runtime, editor, shell, and platform CI. The release workflow must verify the exact main commit before package publication.
