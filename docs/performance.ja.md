# 境界検査の性能

## 増分検査の実験 (2026-11-25)

`cargo test --release -p boundra-cli --test incremental-experiment -- --nocapture` でソース、ファイル追加・削除、エイリアス、マニフェスト、設定変更後に完全検査との結果・範囲の一致を確認します。1,000 ファイル、二つのドメインの合成環境で一貫した性能向上が確認できなかったため、キャッシュはテスト専用のままです。実際のワークスペースとメモリへの影響を評価してから導入します。

Boundra の性能に関する主張は、小さなサンプルでの非公式な観察ではなく、再現可能な合成ワークスペースを使用しています。

## 実行方法

```bash
cargo build --release -p boundra-cli
pnpm benchmark:boundaries
pnpm benchmark:boundaries:large
```

ベンチマークは1,000または10,000個の TypeScript ソースファイルを持つ一時アプリを作成します。すべてのファイルが宣言済みドメインの公開 API を import するため、違反を発生させずにプロジェクト読み込み、import 走査、エイリアス解決、境界評価を計測します。

報告される値：

- 初回実行の実時間（`cold_ms`）
- 2回目以降の実時間の中央値（`warm_median_ms`）
- `/usr/bin/time` が提供する場合の観測された最大常駐メモリサイズ（`max_rss_mb`）
- オペレーティングシステム、アーキテクチャ、Node バージョン、ファイル数、反復回数

## 回帰検出ゲート

CI は意図的に余裕のある上限を使用し、1,000ファイルのスモークベンチマークを実行します。このゲートは通常のランナーのばらつきではなく、重大な性能劣化を検出することが目的です。リリースの判断には、同じ環境で繰り返し測定した結果を比較してください。

## 現在のベースライン

2026-07-03 に取得したローカル基準値（`darwin-arm64`、Node 24.14.0）：

| ファイル数 | コールド | ウォーム中央値 | 最大 RSS |
| ---: | ---: | ---: | ---: |
| 1,000 | 20.74 ms | 18.92 ms | 2.55 MB |
| 10,000 | 163.32 ms | 164.20 ms | サンドボックス内では取得不可 |

各リリース候補でベンチマークを再実行し、重要な結果の変化を対応するリリースノートに記録してください。異なるハードウェアの結果を同等のものとして比較しないでください。Linux CI は `/usr/bin/time` を通じて最大 RSS を報告します。
