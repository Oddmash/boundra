# 경계 검사 성능

Boundra 성능 주장은 소규모 예제의 비공식 관찰이 아닌 재현 가능한 합성 워크스페이스를 사용합니다.

<a id="run"></a>

## 실행

```bash
cargo build --release -p boundra-cli
pnpm benchmark:boundaries
pnpm benchmark:boundaries:large
```

벤치마크는 TypeScript 소스 파일 1,000개 또는 10,000개로 구성된 임시 앱을 생성합니다. 모든 파일이 선언된 도메인의 공개 API를 import하므로 위반사항을 발생시키지 않고 프로젝트 로드, import 스캔, 별칭 해석 및 경계 평가를 측정합니다.

보고되는 값:

- 최초 실행 경과 시간(`cold_ms`)
- 후속 실행 경과 시간 중앙값(`warm_median_ms`)
- `/usr/bin/time`에서 제공하는 경우 관찰된 최대 상주 메모리 크기(`max_rss_mb`)
- 운영체제, 아키텍처, Node 버전, 파일 수 및 반복 횟수

<a id="regression-gate"></a>

## 회귀 검증

CI는 의도적으로 넓게 설정된 상한을 적용하여 1,000개 파일의 스모크 벤치마크를 실행합니다. 이 검증은 러너의 일반적인 편차가 아니라 치명적인 성능 회귀를 감지하기 위한 것입니다. 릴리스 결정에는 동일한 환경에서 여러 차례 실행한 결과를 비교해야 합니다.

<a id="current-baseline"></a>

## 현재 기준값

2026-07-03에 수집한 로컬 기준값(`darwin-arm64`, Node 24.14.0):

| 파일 수 | 최초 실행 | 후속 실행 중앙값 | 최대 RSS |
| ---: | ---: | ---: | ---: |
| 1,000 | 20.74 ms | 18.92 ms | 2.55 MB |
| 10,000 | 163.32 ms | 164.20 ms | 샌드박스에서 측정 불가 |

각 릴리스 후보에서 벤치마크를 다시 실행하고 실질적으로 달라진 결과를 해당 릴리스 노트에 기록하세요. 하드웨어가 서로 다른 결과를 동등한 조건의 결과처럼 비교하지 마세요. Linux CI는 `/usr/bin/time`을 통해 최대 RSS를 보고합니다.
